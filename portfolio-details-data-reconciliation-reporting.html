Project Objective

This portfolio example demonstrates a structured way to compare source and target records, identify differences, and document exceptions so they can be reviewed before reporting or implementation decisions are made.

The example is relevant to operational data checks, including reference data and transaction summaries. The sample records below are fictional and are not taken from a real hospital or client.

Reconciliation Workflow

Use a repeatable process to compare two datasets, confirm that matching keys are consistent, and isolate records that require follow-up.

  • Prepare source and target data with consistent column formats.
  • Match records using an agreed unique key or business reference.
  • Compare key fields, quantities, or values.
  • Separate matched records from exceptions for review.

Data Quality Checks

Checks can help expose common issues before a summary or report is used.

  • Missing records in source or target data.
  • Potential duplicates based on matching identifiers.
  • Differences in values or naming conventions.
  • Blank mandatory fields and inconsistent formats.

Example Spreadsheet Checks

Formulas can support first-pass checks, with the result still reviewed against business rules and source documentation.

  • Duplicate key: =COUNTIF(A:A,A2)>1
  • Compare values: =IF(B2=C2,"Matched","Review")
  • Lookup a reference: =IFERROR(VLOOKUP(A2,Target!A:B,2,FALSE),"Not Found")

Key Deliverables

  • Source-to-target comparison sheet.
  • Summary of matched records and exceptions.
  • Validation checklist for missing or inconsistent data.
  • Issue and follow-up log for unresolved differences.

Approach & Expected Value

A clear reconciliation process makes data differences easier to trace, reduces reliance on manual spot checks alone, and supports more consistent reporting. Final decisions should be confirmed with the appropriate data owner or stakeholder.
