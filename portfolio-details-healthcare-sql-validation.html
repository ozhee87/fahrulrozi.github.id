Project Overview

This case study demonstrates how SQL can support healthcare data quality review by identifying possible duplicate transactions, checking required values, grouping records by input time, and reviewing transaction categories.

The examples use a fictional schema and sample logic for portfolio demonstration. They do not contain real patient, transaction, or hospital data.

01. Duplicate Transaction Review

Identify records that share a transaction number and the same input minute. Such matches are flagged for review rather than treated as confirmed duplicates automatically.

  • Exclude blank transaction numbers and placeholder values such as a dash.
  • Group by transaction number and normalized input minute.
  • Review matched records against source details before taking action.

02. Timestamp & Field Validation

Consistent date-time formatting is essential for reliable grouping and comparison. When timestamps are stored as text in different local formats, normalize them before running time-based checks.

  • Check missing or invalid timestamps.
  • Normalize values to a consistent date-time format.
  • Separate date and time fields when needed for reporting.

Example SQL Query: Possible Duplicate Transactions

This illustrative SQLite query groups records by transaction number and input minute. It assumes input_timestamp is already stored in a format SQLite can parse, such as YYYY-MM-DD HH:MM:SS.

SELECT
    TRIM(transaction_no) AS transaction_no,
    strftime('%Y-%m-%d %H:%M', input_timestamp) AS input_minute,
    COUNT(*) AS record_count
FROM transaction_records
WHERE transaction_no IS NOT NULL
  AND TRIM(transaction_no) NOT IN ('', '-')
  AND input_timestamp IS NOT NULL
  AND strftime('%Y-%m-%d %H:%M', input_timestamp) IS NOT NULL
GROUP BY
    TRIM(transaction_no),
    strftime('%Y-%m-%d %H:%M', input_timestamp)
HAVING COUNT(*) > 1
ORDER BY record_count DESC, transaction_no;

Note: If source timestamps use a format such as DD/MM/YYYY HH:MM, normalize that text to an ISO-compatible format first; SQLite may not parse every locale-specific text format directly.

03. Transaction Category Check

Review selected transaction categories and count records by category. Category labels should follow the agreed terminology used in the source and target systems.

SELECT
    TRIM(transaction_category) AS category,
    COUNT(*) AS total_records
FROM transaction_records
WHERE LOWER(TRIM(transaction_category))
      IN ('tindakan', 'konsultasi')
GROUP BY LOWER(TRIM(transaction_category))
ORDER BY category;

04. Data Quality Checklist

  • Required identifiers are present and meaningful.
  • Timestamp values can be parsed and compared consistently.
  • Category values use expected labels.
  • Potential duplicates are reviewed against source records.
  • Findings and follow-up actions are documented.

Validation Workflow

1

Inspect

Review fields, formats, and missing values.

2

Query

Run duplicate and consistency checks.

3

Verify

4

Expected Value

  • Earlier identification of records requiring review.
  • More consistent transaction timestamps and category values.
  • Clearer evidence for reconciliation and issue follow-up.
  • Repeatable SQL checks that can be adapted to approved schemas.

All table names, fields, and example queries on this page are illustrative. Any real implementation should be validated against the approved database schema and data governance rules.
